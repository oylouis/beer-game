# 规则表（服务端权威计算）

> 说明：《啤酒游戏：牛鞭效应云端模拟》是基于经典啤酒游戏教学机制的非官方复刻，与 MIT 无官方关联。

## 核心角色

| 角色 | 说明 |
| ---- | ---- |
| 零售商 Retailer | 唯一面对最终顾客需求，向批发商下单 |
| 批发商 Wholesaler | 收到零售商订单，向分销商下单 |
| 分销商 Distributor | 收到批发商订单，向工厂下单 |
| 工厂 Factory | 收到分销商订单，通过生产满足需求，无上游 |

只有零售商面对最终顾客需求；上游角色只看到下游递交给它的订单。

## 默认参数（均可配置）

| 参数 | 默认值 |
| ---- | ---- |
| 周期数（周） | 36 |
| 初始库存 | 每角色 12 箱 |
| 初始在途 | 按稳定需求 4 箱/周 预设至前几周可用 |
| 最终顾客需求 | 第1-4周 4箱/周；第5周起 8箱/周；第12周可加 +4 冲击 |
| 订单处理延迟 | 1 周 |
| 运输/发货延迟 | 2 周 |
| 工厂生产延迟 | 2 周 |
| 库存持有成本 | 0.5 元/箱/周 |
| 缺货成本 | 1.0 元/箱/周 |
| 订单约束 | 非负整数，不可撤销 |

## 每周固定流程（服务端状态机唯一权威顺序）

1. 接收到货：各角色把本周期到达的货物加入库存。
2. 满足下游订单 / 顾客需求：优先满足，超出部分记为缺货（backlog）。
3. 记录缺货。
4. 计算库存成本与缺货成本。
5. 玩家下订单（本周期内提交）。
6. 推进延迟队列：订单进入上游订单队列（处理延迟1周），发货/生产沿延迟队列推进。

库存与缺货不会同时为正（缺货即库存为负的体现）。

## 信息隔离

每个玩家只能看到：自己的库存、在途、收到的下游订单、自身成本。
不能看到：全局库存、未来需求、其他角色数据。复盘阶段才展示全局数据。

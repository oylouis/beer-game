## 手工端到端测试清单

### 延迟队列
1. 开房只留零售商为人类，其余 AI。开始后零售商连续下固定订单。
2. 观察批发商收单延迟 1 周、货物到达延迟 2 周是否符合规则表。

### 成本计算
3. 记录某周末端库存/缺货，核对 cost = inv×0.5 + backlog×1.0，累计逐周相加。
4. 极端情况（不下单扛大量需求）确认库存与缺货不同时为正。

### 信息隔离
5. 玩家端无法看到其他角色库存/全局库存/未来需求脚本。
6. 讲师端可看到全局数据与需求脚本。

### AI 合法性
7. AI 决策输入仅取自身历史/在途/收单，不含未来需求；对比需求冲击时 AI 未提前反应。

### 断线重连
8. 玩家玩游戏后刷新页面 → 用 session token 自动 `player:reconnect` 回到原角色，状态不丢。
9. 玩家 socket 断开 → 标记离线；讲师可踢人，也可补 AI 接管。

### 移动端触控
10. 手机浏览器（iOS Safari / Android Chrome）完成：加入→下单→查看图表→复盘。
11. 下单数字键盘触控目标 ≥44px，不依赖 hover。
12. 正确处理 100dvh 与安全区、软键盘遮挡（下单区为 sticky 顶部）。

### 讲师控制
13. 创建房间 → 复制房间码 → 选场景 → 开始/暂停/单步/重置逐项生效。
14. 游戏结束后讲师端可查看/导出复盘 CSV、JSON。

### 重开逻辑
15. 结束后重开：状态清零、周回 0、快照清空，不残留旧数据。

### 持久化与云端
16. 配置 DATABASE_URL 后刷新不丢房间/玩家/快照。
17. 部署后公网 URL 可访问，Socket.io WebSocket 正常。

## 自测用例与预期

| # | 操作 | 预期结果 |
| -- | ---- | ---- |
| A1 | 新手只用稳定需求场景，所有角色由 AI 全链模拟 36 周 | 服务端不抛错，各角色 history=36 条，总成本为正，曲线正常 |
| A2 | 讲师开房，1 玩家加入零售商，其余 3 AI，点击开始 | 加入成功、AI 补位、开始后玩家收到 player:state，周=1 |
| A3 | 零售商玩家提交 `-5`（负数） | 服务端拒绝「订单必须为非负整数」，库存/成本不变 |
| A4 | 需求从 4→8 的冲击周后，让 4 个角色全部用 AI 顺序下单 10 周 | 上游订单方差/需求方差放大倍数 >1，Charts 展现出牛鞭效应 |
| A5 | 玩家下单一周后刷新页面重新进入 | 通过 session token 重连，仍为该角色，周状态与下单保持一致 |
